Incomplete propagation

Something new was added — a preset, a demand axis, an input mode, a catalog row — and it did not reach every place that had to consume it. Propagation is a manual walk with no completeness check, so what is left out is silent.

6

Sibling-template port

A template built by adapting another carries the source's premises and defects. The port's fidelity is not evidence of correctness — it is exactly what hides the problem, because the validation gold standard becomes the copied template rather than the design code.

defect ported from a sibling ×2 member category wired by hand ×2 half-adapted duplication ×1 model ≠ physical joint ×1
3

Unwritten assumption

An assumption the equations rely on was never written as a check. Because the formulas stay arithmetically evaluable when it breaks, the invalid configuration degrades silently into a plausible number instead of failing.

constructability not modelled ×2 drawing geometry is analysis input ×1

Local defect

Confined to one template, with no structural pattern behind it. Worth noting mainly because it is the smallest family: only two of twenty tickets are the isolated mistake that bug triage implicitly assumes.

Time from introduction to detection 19 of 20 dated

The pattern is the point: the longest-lived defects are the ones that never produce an alarming number. An over-conservative result oversizes a member and nobody files a ticket, so it accumulates years — while the one defect caught the same day it shipped was caught by an automated reviewer, not by testing.

How they fail, and who found them

Half of these defects are an absence — a check that is missing, an output that never renders, a demand that never arrives. An absence produces no wrong number, which is why numerical-correctness testing cannot see it and why customers find so many.

What follows from this

Four measures, each covering a whole family rather than one ticket. Every one is mechanical — no engineering judgement needed to run it.

covers 9 tickets

Propagation matrix as a PR artefact

Adding a preset, a load axis or an input mode must ship with the matrix of every gate, limit state and calculation path that consumes it, each marked reaches / not applicable + reason. Turns a silent manual walk into something auditable.

covers 9 tickets

Static reachability and identity lints

Three rules with no judgement in them: a visible widget may only reference visible widgets; a preset value present in some gates of a field but absent from others is a warning; a check's conditions must evaluate the widget's own referenceId.

covers 6 tickets

Never validate a port against its source

A template adapted from a sibling must be validated against the design code and an independent hand calc. The source's numbers agreeing proves only that the defect came along. State which of the source's premises still hold.

covers 5 tickets

Fixtures that break the defaults

Give same-kind inputs deliberately unequal values (w_s ≠ w_fp), make project-default groups differ, test the minimum of every count, and cross every optional feature with the others. Shared defaults hide a whole defect class.
